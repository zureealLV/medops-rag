## 1. Ingestion benchmark

Fixtures are generated by `evals/benchmark_ingestion.py`. OCR is warmed once; each listed format is then
parsed three times. These figures are development-host measurements, not portable hardware guarantees.

| Input | Elements/modalities | Median | Mean | Interpretation |
| --- | --- | ---: | ---: | --- |
| Markdown | 2 text | 0.029 ms | 0.412 ms | decoding overhead is negligible |
| native PDF | 1 text | 1.152 ms | 109.389 ms | first pypdf import dominates mean; steady parse is fast |
| DOCX + table + picture | 2 text, 1 table, 1 OCR | 1345.708 ms | 1350.387 ms | OCR dominates container parsing |
| PPTX + picture | 1 text, 1 OCR | 1505.882 ms | 1541.399 ms | OCR dominates container parsing |
| PNG | 1 OCR | 1456.990 ms | 1461.576 ms | request-thread OCR is too expensive at scale |
| scanned PDF | 1 OCR | 1651.417 ms | 1621.495 ms | render + OCR cost is comparable to direct image OCR |

**Decision:** use native PDF text first and invoke rendered-page OCR only for text-poor pages. Move OCR to a
background ingestion worker before beta load testing.

## 2. Deterministic retrieval benchmark

Corpus: 6 synthetic documents, 25 answerable questions. Because Top-5 almost covers the corpus, Hit@1 and
MRR@5 are the useful diagnostics.

| Strategy | Hit@1 | MRR@5 | Mean latency | p95 |
| --- | ---: | ---: | ---: | ---: |
| token overlap | 0.96 | 0.98 | 5.781 ms | 6.779 ms |
| hashing vector | 0.88 | 0.9333 | 5.807 ms | 6.872 ms |
| weighted hashing + overlap | **1.00** | **1.00** | 6.330 ms | 7.185 ms |
| BM25 | **1.00** | **1.00** | **5.713 ms** | **6.524 ms** |
| BM25 + hashing RRF | 0.92 | 0.96 | 5.755 ms | 7.076 ms |

**Decision:** RRF is not automatically superior. Fusing a weak hashing retriever with a saturated BM25
retriever reduced Hit@1. Keep multiple explicit strategies and require held-out evidence before changing the
default.

## 3. Local semantic and reranking benchmark

Dense model: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
Reranker: `BAAI/bge-reranker-base`
Model files were already cached; load time excludes network download. Candidate limit for reranking: 10.

| Strategy | Hit@1 | MRR@5 | Mean query latency | p95 |
| --- | ---: | ---: | ---: | ---: |
| hashing dense | 0.88 | 0.9333 | 0.187 ms | 0.404 ms |
| multilingual MiniLM dense | 0.88 | 0.9280 | 124.153 ms | 225.281 ms |
| BM25 | **1.00** | **1.00** | **0.424 ms** | 1.214 ms |
| BM25 + MiniLM RRF | 0.96 | 0.9733 | 124.188 ms | 225.296 ms |
| fused Top-10 + BGE reranker | **1.00** | **1.00** | 1198.455 ms | 1339.681 ms |

Additional startup/index evidence:

- cached MiniLM load: 1056.661 ms;
- cached BGE reranker load: 4116.388 ms;
- six-chunk MiniLM indexing: 1466.439 ms;
- local model cache used for this experiment: approximately 1.3 GiB and excluded from Git.

**Decision:** on this lexical toy corpus, BM25 ties the best quality at a fraction of the latency. BGE restores
the fused pipeline to Hit@1 1.00 but adds about 1.07 seconds over dense+fusion, without measurable quality
gain. Dense and reranking remain experimental until the V2 dataset contains semantic paraphrases, OCR noise,
tables, and visual questions.

## 4. What these results do not prove

- Six documents and 25 answerable questions are not production evidence.
- Hit@5 is nearly meaningless at this corpus size.
- The dataset mostly shares vocabulary with the documents, favoring BM25.
- No visual-only question or chart reasoning case exists yet.
- No concurrency, queue, or large-file performance was measured.
- The current MiniLM FastEmbed implementation emits a pooling migration warning; the model/provider version
  must be frozen before it can become a production profile.

## 5. Next benchmark version

`synthetic-operations-v2` must include at least:

- 100 questions split into development and held-out test sets;
- short/ambiguous queries, synonym paraphrases, exact error codes, negation, and multi-hop questions;
- distractor documents with overlapping vocabulary;
- native and scanned PDF, DOCX tables, PPTX diagrams, screenshots, and image-only evidence;
- expected document, element, page/slide, and when applicable bounding box;
- answerable, insufficient-evidence, unsafe-instruction, cross-tenant, and medical-advice-denial cases;
- quality, latency, memory, token, and failure-rate metrics.

Only the held-out V2 results may decide the default embedding, fusion, reranker, HyDE trigger, and abstention
threshold.
